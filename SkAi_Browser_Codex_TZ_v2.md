# Sk/Ai Browser — техническое задание для Codex
**Версия:** 2.0 · **Дата:** 12 ноября 2026 г. · **Статус:** проектное ТЗ для реализации MVP и дальнейших этапов

## 1. Цель и границы
Создать самостоятельный бесплатный браузер **Sk/Ai** для Windows 11 x64, ориентированный в том числе на слабые ПК (целевой класс: 8 ГБ ОЗУ и менее). Не модифицировать и не переупаковывать Яндекс.Браузер. Браузер должен сочетать полноценный веб-сёрфинг, встроенную правую ИИ-панель, приватность, управляемую ИИ-помощником безопасность и голосовое управление.

**Разделение продуктов:** Sk/Ai Browser — пользовательский браузер. Sk/Ai Agent — отдельный агент разработки на базе Codex. Функции автономного программирования и настройки Windows относятся к Agent и не должны бесконтрольно попадать в Browser.

**Не обещать недостижимого:** бесплатный облачный ИИ зависит от условий поставщика и бюджета; отсутствие телеметрии продукта не гарантирует отсутствия сетевых обращений Chromium, пока они не проверены; блокировка рекламы/трекеров не может гарантировать 100% защиты; слабый ПК не гарантирует быструю локальную генерацию.

## 2. Продуктовая модель: три режима одного ИИ
Все режимы используют единый UI чата, историю диалогов, инструменты управления браузером и голосовой интерфейс.

1. **Бесплатный облачный ИИ по умолчанию:** предпочтительно Qwen, без необходимости скачивать модель или вводить API-ключ пользователю. Допускаются прозрачные лимиты. **Блокирующее условие запуска:** подтвердить легального поставщика, его API/условия, доступность без пользовательского ключа и финансовую устойчивость. Не встраивать общий секрет поставщика в клиент. Если без собственного сервера/прокси это невозможно, явно оформить решение и затраты; не выдавать демо за готовый бесплатный сервис.
2. **Локальный ИИ:** опциональная установка из «Настройки → ИИ → Локальные модели». Qwen — рекомендуемая, но не единственная совместимая модель. Никакой большой модели в стандартном установщике. Формат GGUF и llama.cpp — исходная техническая гипотеза, подлежащая проверке. После загрузки локальный режим работает без сети в пределах возможностей модели и инструментов.
3. **Собственный API (BYOK):** «Настройки → ИИ → Подключения». Поддерживаемые адаптеры для OpenAI, Qwen-совместимых API, Gemini, Claude, DeepSeek и других провайдеров по мере реализации. Ввод ключа, тест соединения, выбор модели, назначение по умолчанию, удаление ключа. Подписка на чат-продукт не равна API-биллингу.

Переключатель модели непосредственно в чате. При смене провайдера локальная история сохраняется; отправка прежнего контекста новому провайдеру требует явного выбора пользователя. Не обещать одинаковых возможностей у всех моделей; UI должен отражать поддержку tool calling, streaming, изображений и т. п.

## 3. Локальные модели: UX и жизненный цикл
- Каталог проверенных моделей: название, версия, лицензия, размер файла, примерные требования к RAM/диску, ожидаемые ограничения и совместимость.
- Источники: официальные/проверенные репозитории (например, Hugging Face), с зафиксированными версиями и SHA-256. Не доверять произвольным ссылкам без проверки.
- Скачивание с прогрессом, паузой/возобновлением, повтором после обрыва, проверкой свободного места и контрольной суммы.
- Выбор папки хранения, обновление, удаление, выбор между несколькими установленными моделями.
- Предварительная оценка ресурсов, безопасная отмена запуска при нехватке RAM, отсутствие принудительной загрузки модели при старте браузера.
- Не загружать произвольный исполняемый код из репозитория моделей; проверять лицензии и совместимость.

## 4. Интерфейс и фирменный дизайн
**Композиция:** привычные вкладки сверху; под ними навигация и адресная строка; основная область сайта слева, ИИ-панель справа. Правая панель изменяет ширину, сворачивается, разворачивается, при необходимости отсоединяется в отдельное окно. Диалог не теряется при перестройке.

**Визуальная система:** Soft Aurora — основной стиль; Quiet Mist — светлая тема; Deep Space — тёмная тема. Мягкие фиолетовые и голубые акценты, спокойная типографика, небольшие скругления, ясные состояния наведения/фокуса, без тяжёлого стекломорфизма. Поддержка системной темы и настройки анимаций.

**Брендинг:**
- Полное название: **Sk/Ai**.
- Самостоятельный фирменный знак для иконки приложения и панели задач: **/Ai**.
- При открытии ИИ-панели буквы **Ai физически выдвигаются из-за символа /** в надписи **Sk/Ai** (маска/клиппинг и перемещение, не только fade-in); при закрытии — обратное движение.
- Вокруг **/Ai** — аккуратное фиолетово-голубое свечение: слабое в покое, усиливается при открытии, мягко пульсирует при генерации, реагирует на голосовую активацию. Читаемость символов сохраняется.
- Анимация короткая, на композиторе, без тяжёлых эффектов; `prefers-reduced-motion`/отключение анимации. Предусмотреть статические состояния для слабых ПК.

**ИИ-панель:** список/история диалогов, выбор модели, поле ввода, отправка, кнопка микрофона, индикатор выбранного режима (облако / свой API / локальный), индикатор работы, понятные сообщения об ошибках/лимитах.

## 5. Голосовое управление — тот же ИИ, не отдельная LLM
- Голос — альтернативный способ общения с **текущей выбранной моделью**: STT → текущая LLM + разрешённые инструменты → TTS.
- Один контекст чата для голоса и текста; пользователь может переключаться между ними.
- По умолчанию **push-to-talk** (кнопка микрофона). Опционально активация ключевой фразой, например «Привет, Qwen» или пользовательским именем помощника.
- Имя помощника не обязано совпадать с названием LLM. Настройка имени, языка, голоса, чувствительности и режима озвучивания.
- Детектор ключевой фразы по возможности лёгкий и **локальный**; непрерывный звук не передавать в облако. Для произвольных имён качество распознавания может различаться: проверить технологию и предусмотреть ограниченный набор надёжных вариантов/обучение.
- STT/TTS: локальные и/или облачные адаптеры с понятными требованиями, разрешениями, стоимостью и ограничениями. Не считать STT/TTS бесплатными автоматически.
- Микрофон только по явному разрешению; постоянный видимый индикатор прослушивания, быстрый mute, полное выключение функции; никакой скрытой записи.
- Голосовой запрос вроде «найди информацию о ...» запускает поиск доступным браузерным инструментом и озвучивает ответ с возможностью открыть источники.

## 6. AI Security и управление браузером
### 6.1 Базовая безопасность — независимо от LLM
Механизмы Chromium/движка, контроль разрешений сайтов, защита от опасных загрузок и навигаций, блокировка трекеров/рекламы по проверяемым правилам, безопасная обработка HTTPS, изоляция процессов и обновления. Не отключать базовую защиту из-за отсутствия интернета, смены модели или лимитов API.

### 6.2 Опциональный фоновый AI Security
В «Настройки → Безопасность → AI Security»: включить/выключить, уровень чувствительности, типы событий, уведомления, ограничения CPU/RAM, политику передачи данных. По умолчанию локальные дешёвые эвристики и событийные проверки; LLM только по необходимости. **Никакой автоматической отправки полного содержимого страниц, паролей, cookies или личных данных в облако**. Для облачного анализа — отдельное явное согласие и минимизация передаваемых данных.

### 6.3 Browser Control
ИИ получает **типизированные разрешённые инструменты**, а не произвольный доступ к файловой системе или системным API: открыть/закрыть/найти вкладку, поиск, история, закладки, настройки разрешений сайта, управление загрузками в допустимых пределах. Примеры: «закрой остальные вкладки», «найди скачанный файл», «запрети микрофон этому сайту».

- Чтение состояния — минимальные разрешения; изменение настроек защиты, очистка истории, удаление файлов, отправка данных и иные чувствительные операции — явное подтверждение.
- Ограничить инструменты доменами, контекстом и правами; журнал действий и возможность отмены там, где возможно.
- **Защита от prompt injection:** текст веб-страниц и результаты поиска — недоверенные данные, не инструкции для инструментов.
- Ни одна модель, в том числе BYOK, не получает безусловных полномочий.
- Для действий на внешних сайтах, связанных с платежами, отправкой сообщений или учётными записями, предусмотреть отдельные подтверждения.

## 7. Приватность и сеть
- Не собирать собственную поведенческую аналитику/рекламные идентификаторы; не продавать данные и не показывать собственную рекламу.
- Блокировка известных трекеров, сторонних cookies (с настройками совместимости), навязчивых рекламных элементов; исключения для сайтов по выбору пользователя.
- Не симулировать юридическое согласие на cookies. Не обещать, что блокировка рекламы не сломает сайты.
- Раздельные политики приватности для локального ИИ, бесплатного облака и BYOK: объяснять, какие данные уходят поставщику.
- API-ключи хранить средствами защиты Windows (например, DPAPI/Credential Manager); не писать в логи, не экспортировать в профили открытым текстом. Для прямого BYOK-запроса ключ не должен проходить через сервер Sk/Ai.
- Не отключать обновления безопасности браузерного движка ради «отсутствия телеметрии». Сетевые обращения движка документировать и тестировать.

## 8. Базовые функции браузера
Вкладки, несколько окон, адресная строка и поиск с выбором поисковой системы, история, закладки, загрузки, менеджер разрешений, профили, восстановление сессии, поиск по странице, горячие клавиши, настройки масштабирования, импорт данных при наличии безопасного механизма, светлая/тёмная тема, локализация RU с архитектурой для других языков, доступность с клавиатуры и экранным диктором.

## 9. Настройки: структура
- **Внешний вид:** тема, плотность UI, анимации, свечение логотипа, положение/ширина ИИ-панели.
- **ИИ → Общие:** активная модель, облако / BYOK / локальная, история и политика контекста.
- **ИИ → Локальные модели:** каталог, скачивание, выбор папки, обновление/удаление.
- **ИИ → Подключения:** API-провайдеры, ключи, проверка, выбор моделей.
- **ИИ → Голос:** включение, push-to-talk, ключевая фраза, имя помощника, STT/TTS, голос, язык, микрофон.
- **Безопасность → AI Security:** фоновый анализ, чувствительность, события, ресурсы, приватность и уведомления.
- **Конфиденциальность:** блокировки, cookies, разрешения, исключения, удаление данных.
- **Система:** производительность, обновления, диагностика без скрытой телеметрии.

## 10. Архитектура и ограничения производительности
Предварительный стек для исследования: C++20, Win32, CEF/Chromium, CMake/MSVC, HTML/CSS/JS для UI, llama.cpp для локальных GGUF. **Codex обязан сначала провести технический spike**, оценить лицензии, поддержку обновлений безопасности, стоимость сопровождения CEF и возможные более лёгкие альтернативы. Не фиксировать стек без измерений.

Разделить модули: Browser Core, UI Shell, AI Provider Adapter, Local Model Manager, Voice STT/TTS/Wake-word, AI Security, Browser Tool Gateway, Profile/Secrets, Updates. API адаптеров должен быть расширяемым.

Целевые измерения на тестовом ПК с 8 ГБ RAM: холодный старт, RAM с 1/5/10 вкладками, CPU в простое, фоновой защите и ожидании ключевой фразы, отклик UI, расход диска и нагрузка при локальной модели. **Числовые нормативы определить после прототипа**; не заявлять гарантии до тестов. Тяжёлые модели и микрофон не должны запускаться без выбора пользователя.

## 11. Этапы работ для Codex
**Этап 0 — проверка реализуемости:** сравнить движки и архитектуру, лицензии, стратегию обновления безопасности, поставщиков бесплатного облачного Qwen, доступность STT/TTS и wake-word, угрозы/затраты; зафиксировать ADR и риски.

**Этап 1 — Browser MVP:** полноценное окно, вкладки сверху, адресная строка, сайт, базовые настройки, профили/история/загрузки, темы, правая ИИ-панель и фирменная анимация /Ai; сборка Windows x64.

**Этап 2 — единый ИИ:** провайдерный интерфейс, чат, переключение моделей, BYOK с защищённым хранением ключей; бесплатный облачный режим — только после подтверждения поставщика и схемы оплаты; контекст и согласие на передачу.

**Этап 3 — локальный ИИ:** каталог, загрузчик, проверки, llama.cpp или обоснованная альтернатива, управление ресурсами, offline-тесты.

**Этап 4 — Security & Control:** базовые фильтры и разрешения, AI Security с настройками, контролируемые инструменты, подтверждения, защита от prompt injection, аудит.

**Этап 5 — голос:** push-to-talk, STT/TTS, общий чат, затем опциональная локальная ключевая фраза и пользовательское имя.

**Этап 6 — выпуск:** профилирование на слабых ПК, доступность, тесты безопасности, установщик/деинсталлятор, подпись при наличии сертификата, обновления, CI/CD GitHub Actions, документация.

## 12. Приёмочные критерии
1. Устанавливается и запускается на Windows 11 x64 без Яндекс.Браузера.
2. Вкладки сверху; сайт и правая ИИ-панель работают одновременно; панель меняет размер, сворачивается и отсоединяется без потери диалога.
3. Логотип **/Ai** и полное имя **Sk/Ai** корректны; **Ai выдвигается из-за /**, а не только проявляется; свечение и анимации отключаемы.
4. Единый чат работает с выбранным провайдером; BYOK-ключ защищён; смена провайдера не отправляет старый контекст без согласия.
5. Локальная модель скачивается только по выбору пользователя, проходит проверку SHA-256, запускается offline, удаляется без переустановки браузера.
6. Голосовой и текстовый ввод используют один диалог; при отключённом микрофоне нет фонового прослушивания; ключевая фраза — отдельная опция.
7. Базовая защита не зависит от LLM; AI Security включается отдельно; опасные команды требуют подтверждения.
8. Проведены измерения производительности на слабом ПК, описаны ограничения и регрессии.
9. Есть автоматизированные тесты, воспроизводимая сборка, инструкции разработчику и пользователю, безопасный механизм обновлений.

## 13. Указания Codex на старт
1. Сначала изучить это ТЗ, выявить противоречия и неизвестные зависимости. Не начинать с большого монолита.
2. Создать репозиторий с `README.md`, `ARCHITECTURE.md`, `DECISIONS.md`, `TASKS.md`, `SECURITY.md`, `AGENTS.md`, тестовым планом и инструкциями сборки.
3. Подготовить технический spike и небольшой запускаемый прототип интерфейса Windows: вкладки сверху, сайт слева, ИИ-панель справа, анимация **Sk/Ai → /Ai**.
4. Проверить реальную производительность и поддерживаемость движка до окончательного выбора.
5. Работать итерациями: код → сборка → тесты → исправление → отчёт. Не объявлять функцию готовой без проверок.
6. Все ключи/токены — только в защищённом хранилище/секретах CI; не обходить UAC, не отключать системную защиту.
7. Если внешний сервис или лицензия не подтверждены, пометить зависимость как **BLOCKED**, предложить варианты и не подменять её фиктивной реализацией.

## 14. Открытые решения
- Юридически и финансово устойчивый поставщик бесплатного облачного Qwen.
- Окончательный веб-движок и стратегия его security updates.
- Конкретные версии Qwen/GGUF и нижняя граница RAM для каждой.
- Реализация STT/TTS и произвольных wake words, языки и стоимость.
- Точные макеты, иконка /Ai, длительность анимаций и дизайн-токены после UI-прототипа.
- Модель распространения, лицензии зависимостей, подпись установщика и инфраструктура обновлений.

**Приоритет:** работоспособность, безопасность, приватность и низкое потребление ресурсов важнее декоративных эффектов.
